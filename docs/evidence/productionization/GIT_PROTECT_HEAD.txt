    fix(model-runtime): prevent alternating chat failures from model residency races
    
    Root cause:
    - Background probes and embedding requests could evict or replace the
      active chat runner immediately after a successful response.
    - Subsequent requests raced a cold or CPU model load, leading to
      intermittent FIRST_PROGRESS_TIMEOUT failures.
    
    Changes:
    - Hold chat priority briefly after successful completion.
    - Use consistent context length for health probes.
    - Validate GPU residency and expected context before streaming.
    - Prevent in-stream model reloads.
    - Make embedding paths respect interactive chat priority.
    
    Results:
    - Eliminates alternating success/failure behavior.
    - Preserves warm GPU residency across consecutive chats.
    - Verified with repeated multi-turn conversations and mixed workloads.
    
    Regression:
    - 28/28 consecutive requests passed with stable GPU residency.
